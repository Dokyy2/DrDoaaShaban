# عيادة د. دعاء شعبان — نسخة الإدارة المحلية

> **الحالة الحالية بتاريخ 2026-11-18:** النسخة المحلية `05 - Admin Supabase Trial 2026-11-14` تعمل على قاعدة التجربة `gtpmzbjakfvjpvpliwnj`. نجحت اختبارات المصدر الحالية (51/51) وفحوص تركيب JavaScript، وتمت مراجعة صفحات الإدارة بحساب المالك والسكرتارية. المستخدم أكد عمليًا نجاح تعديل الصلاحيات وإضافة المصروف بحساب السكرتارية. تفاصيل الإغلاق وحدوده في [تقرير جاهزية النسخة](docs/RELEASE_READINESS_2026-11-18.md). لم يُرفع هذا المجلد إلى GitHub ولم تُنشر نسخة جديدة.

هذه نسخة تجريبية محلية للحجز ولوحة الإدارة. **قاعدة Supabase هي المصدر الأساسي للحجز والإدارة** في هذه النسخة. بعد إغلاق الحالة بزيارة مكتملة أو إلغاء أو عدم حضور، تُرسل لقطة مرجعية إلى تبويب `Admin Closed Archive` في ملف Google Sheet. الشيت ليس مصدر تشغيل أو تعديل للحجوزات في هذه النسخة؛ إصدار `main` للحجز دون إدارة يظل مستقلًا.

## التشغيل والوصول

- افتح المشروع من خادم محلي، لا بفتح `index.html` مباشرةً.
- الموقع المحلي: `http://127.0.0.1:5501/`
- لوحة الإدارة: `http://127.0.0.1:5501/dashboard/`
- الدخول بحساب Supabase مفعّل ودور `secretary` أو `doctor`.
- قاعدة التجربة تحتوي السجل السابق للمراجعة؛ لم تُحذف الحجوزات أو ملفات المريضات.

## تدفق البيانات

1. حجز المريضة يرسل إلى Supabase Edge Function `clinic-db-booking`.
2. الدالة تستدعي `public.create_booking` وتُسجل بيانات الحجز والأحداث داخل قاعدة Supabase. رقم الطلب ثابت وتُعاد نتيجة الحجز نفسه عند تكرار الطلب، كما تُسلسل الدالة فحوصات التكرار والسعة اليومية.
3. لوحة الإدارة تقرأ الحجوزات والإعدادات من Supabase، وتحفظ تحديثات الحالات والدفع والملاحظات هناك مع سياسات RLS حسب دور المستخدم.
4. عند إغلاق الحالة، ينشئ Supabase سجل أرشفة محدودًا قابلًا لإعادة المحاولة، ثم يكتب Apps Script بيانات الحالة التشغيلية والدفع المتاحة إلى تبويب `Admin Closed Archive`. لا تُرسل المرفقات أو الملاحظات الطبية الخاصة إلى الأرشيف.

## إدارة فريق العيادة — المرشح المحلي

- شاشة إدارة الفريق تظهر للطبيبة فقط، وتتيح إرسال دعوة، وتغيير دور طبيبة/سكرتارية، وإيقاف الدخول، مع سجل تدقيق لهذه الإجراءات.
- تم تطبيق `supabase/15_clinic_team_management.sql` ونشر Edge Function باسم `clinic-team-admin` على مشروع Supabase التجريبي `ccuharkcusmsjdxfuamq` يوم 2026-11-09. إعداد Verify JWT معطل للوظيفة لأن الكود يتحقق يدويًا من bearer token ودور الطبيبة. لا تكرري الترحيل؛ تحققي من Auth Redirect URLs قبل إرسال أول دعوة.
- تحتاج الدالة متغيرات الخادم `SUPABASE_URL`, `SUPABASE_ANON_KEY`, و`SUPABASE_SERVICE_ROLE_KEY`. لا تضعي المفتاح السري في `js/config.js` أو أي ملف واجهة.
- أضيفي عنوان لوحة الإدارة المحلية المطابق للمنفذ المستخدم إلى قائمة Redirect URLs في Supabase Auth قبل إرسال دعوات إلى البريد. عند التشغيل الافتراضي على 5501، أضيفي `http://127.0.0.1:5501/dashboard/` و`http://localhost:5501/dashboard/`.
- واجهة الفريق وتعديل عناوين العودة محليان في هذا المرشح. ترحيل الفريق ودالته موجودان على مشروع التجربة؛ لا ترسلي دعوات قبل إضافة عنوان لوحة الإدارة المطابق إلى قائمة Auth Redirect URLs. لم تُرسل دعوة في هذه المراجعة.
5. فتح `index.html` كملف `file://` فقط يشغّل معاينة غير متصلة ولا يحفظ حجوزات.

## الملفات المهمة

- `dashboard/`: واجهة الإدارة، قراءة وكتابة مباشرة إلى Supabase.
- `js/config.js`: عنوان Supabase ومفتاح النشر العام فقط.
- `js/bridge-client.js`: اتصال الحجز بالدالة `clinic-db-booking`.
- `supabase/functions/clinic-db-booking/index.ts`: دالة الحجز الخادمية.
- `supabase/08_supabase_canonical_admin.sql`: مرجع الهجرة المطبقة؛ لا تعيدي تشغيلها يدويًا.
- `supabase/09_role_financial_separation.sql`: حدود قراءة البيانات المالية والملاحظات.
- `supabase/10_booking_idempotency_and_atomic_limits.sql`: رقم الحجز الثابت ومنع التكرار وتجاوز السعة.
- `supabase/11_closed_case_sheet_archive.sql`: سجل أرشفة مغلق ومحمي، ينشئ لقطة للحالة عند الإغلاق.
- `supabase/12_closed_case_archive_fields.sql` و`13_closed_archive_service_policy.sql`: حقول مرجع الشيت وسياسة وصول الخدمة فقط.
- `google-apps-script/commercial/Code.gs`: كود الأرشيف في تبويب مستقل وإعادة محاولة الصفوف المعلقة؛ نشر Apps Script ما زال خطوة لازمة قبل تشغيله فعليًا.
